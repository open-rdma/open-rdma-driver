## 下周规划

### 1. 继续稳定 `cocotb-pcie` 测试入口，补齐可回归的 PCIe 仿真验证链路

- 基于当前已经接入的 `pcie_loopback` 路径，继续收敛 `tests/common/test_common.sh`、`tests/base_test/scripts/test_pcie_loopback_sim.sh` 与 `open-rdma-rtl/test/cocotb` 之间的启动、退出和日志协同逻辑，重点处理公共清理逻辑中仍然存在的 `TODO`
- 结合 `run_pcie_system_test`、`FLOW=pcie`、`compile_verilator` 和 `BLUERDMA_IMMFAIL_ENABLE_TIME` 当前的实际代码路径，把 PCIe 仿真从“可运行”进一步推进到“可重复回归”，减少不同构建参数、不同后端或多轮执行时的环境抖动
- 在现有 loopback 基础上，补充更贴近 PCIe 事务行为的验证重点，包括配置访问、Requester/Completer 转发、完成包处理和 reset 时序问题，为后续定位 driver 与 RTL 之间的 PCIe 交互问题提供更稳定入口

### 2. 驱动 ring buffer 模块继续重构，进一步统一抽象并为硬件演进预留空间

- 继续围绕 `rust-driver/src/ring/spec.rs`、`rust-driver/src/ring/buffer/mod.rs`、`producer.rs` 和 `consumer.rs` 收敛 ring 抽象，明确 `RingSpec`、`RingPtr`、`DmaBuffer` 与 CSR 同步之间的职责边界
- 结合当前 `SendRingSpec(pub(crate) usize)`、`MetaReportRingSpec(pub(crate) usize)` 这类带通道索引的实现，进一步梳理“ring trait 关联常量”和“实例化参数”的关系，减少后续扩展不同 ring 类型或修改硬件 ring 布局时的重复适配成本
- 参考现有硬件/仿真测试与性能验证结果，继续检查 ring buffer 在批量写入、可用空间计算、tail/head 同步和错误处理上的接口设计，使其既能支撑后续硬件改动，也能为更细粒度的调试与性能分析提供更清晰的基础

### 3. 推进 ACK/NAK 路径重构，解决单 QP 单 bitmap 带来的错误耦合问题

- 结合 `open-rdma-rtl/src/AutoAckGenerator.bsv`、`PsnContinousChecker.bsv` 以及现有 `bitmap_tracking_analysis.md` 中描述的实现，重新审视当前“每个 QP 维护一个 bitmap 窗口”的设计边界
- 当前实现里 bitmap 以 QP 为粒度存储，并在窗口滑动时通过 `newEntry.data | newestAlreadyExistEntry.data` 合并状态；这在多通道并发和长 WQE 场景下，容易把本不相关的 WQE 接收状态耦合在一起，进而在没有真实丢包时也触发 NAK
- 下周计划重点论证并推进更细粒度的 bitmap 方案，优先考虑按 WQE 或等价事务粒度拆分 ACK 跟踪状态，重新理顺 auto-ack 生成、meta report 描述符输出以及驱动侧 `recv_table` / `send_table` 的配合关系，为后续修复错误 NAK、改善重传判断和支撑更长事务打下基础
