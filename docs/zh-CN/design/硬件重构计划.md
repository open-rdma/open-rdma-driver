# 硬件ack重构计划

## 问题

当前的 psn 是按照每个qp一套的，但是目前硬件处理包的时候是按照四通道并行进行处理的，但是这样的话有可能造成说 psn 128 的包比 psn 0的包先到达 mkAutoAckGenerator，这样会导致bitmap 进行一次丢包shift，但实际上包没有丢。

有没有一种更好的 psn 处理机制，比如说给每个 wqe 一套单独的 psn，比如说最大为128，这样就不会发生上述bug。

### 当前的设计

本质上市发送/接收端四通道分别处理带来了乱序，有没有一种办法，在发送和接收端通过某种反馈机制，使其没有那么乱序？
比如说 rq 一直通过网络给sq 反馈说哪边积压的比较多

### 每个 wqe 一套单独的 local_seg_idx

这样的话，mkAutoAckGenerator 需要维护的是固定数量的 wqe 的bitmap。
两种方案：

1. 只有接收端给发送端反馈了说这个wqe 空位已经空出来了，发送端才会继续发送，这样的话本质上相当于给最大的inflight 包的数量设置了一个上限，而且这个反馈通路的用时还需要讨论
2. 轮着几个 wqe 空位进行发送，可以设置某种标志位，用于区分同一个wqe 空位的不同请求，这样的话其实并未解决乱序问题，本质上相当于大幅扩展了 psn bitmap的长度，总长度相当于 "wqe空位数量 * 每个wqe最多有几个包"，又或者可以说，在qp内部又做个多qp复用

同时对于第一种方法，还有个问题就是失去了 bitmap shift 检测。

## 重构目标

1. 对于特定操作保序
2. 重传策略
3. 大规模情况下，拥塞控制如何解决
4. gpu friendly
比如在矩阵乘法中
